# Mind Ready — what changed between 27 and 30 September 2026

Versions 1.7.2 and 1.7.3, branch `readiness-verdict-and-prep-fixes`.
Every item below was driven by a real workbook going through the tool.

## 1. One verdict: is this file acceptable by Mind?

- Every analysis, Apply and recalculation now answers one question with three states:
  **blocked** (a REQUIRED rule fails — Mind's converter refuses the file or computes it wrong),
  **unverified** (nothing blocks, but this version was not recalculated in Excel yet, or the
  recalculation found new formula errors), **ready** (nothing blocks and a clean recalculation).
- Each blocking problem says how it gets fixed: a Prep repair, "Prep looked and left it for
  review", or the assistant / by hand. A banner under the top bar shows the verdict, the
  blocking list and the single next step.
- Findings and Prep actions carry a level: **blocking** (Mind needs it) or **optional**
  (Mind reads the file as it is; the change improves it). Findings gained a Level column and a
  "Blocking only" filter; Prep is split into *Blocking / By hand / Optional*. Blocking repairs
  are ticked by default.

## 2. Apply: it really writes, and it says what it did

- **Bug fixed: an Apply that wrote nothing.** On a workbook saved with "read-only
  recommended", Excel opened the working copy read-only (alerts are off), `Save()` silently
  wrote a copy into the user's OneDrive *Documents* folder, and the tool reported
  "38 changes applied, verified" while the file was byte-identical to the original — the
  blocking problem came back after every round. Now: Excel is told to ignore the
  recommendation, every in-place write refuses a read-only workbook, the save is checked
  against the file itself, and an output identical to its source is reported as *nothing
  written*.
- **Outcome report after every Apply** ("What the last Apply did"), in Prep and in the Fix
  panel: for each repair, the changes written and refused, the rule's status and cell count
  before and after, what is still planned or left by hand, and a verdict — *resolved*,
  *partly*, *written but no effect*, *not written*. It also lists repairs that appeared in the
  new version, rules that got worse, and the blocking problems before/after with who acts
  next. A blocking repair that resolved its problem stays visible as *Resolved* instead of
  vanishing; a repair that came back says "back after the last Apply — it had no effect".
- **Real progress while applying**: the stage (copy, write, save, verify, change log,
  re-analyze), the changes written so far, the elapsed time — from the backend's own status,
  not a timer.
- **Applied-changes gauge** in Prep: blocking and optional changes *written / still planned /
  refused*, plus one chip per Apply (`v2 +167 · resolved REF-001`, `v3 +13`, …). The repair
  gauge in the Fix panel and on Findings shows the total written.
- **Prep gauge**: the four steps to Mind with "you are here", one bar per kind of work, the
  figures of every analysed version, and a "not converging" alert when three rounds in a row
  plan as much work as before.
- Every Excel write is read back (a silent no-op is never reported as applied); writes into
  a merged range other than its first cell are refused up front with the reason.

## 3. New or corrected detections (rules)

- **FRM-003 — spilled-range references** (`A1#`, stored as `ANCHORARRAY`): Mind refuses
  them ("Unsupported formula: ANCHORARRAY()"). Now blocking, with a Prep repair that
  replaces each reference by the fixed range the spill covers today, on the same sheet or
  across sheets, keeping absolute references.
- **REF-001 — broken references**: formulas built on a broken *range* are replaced by a
  whole `=NA()` (own action, own checkbox, caution note). New: names that **do not exist**
  in the workbook are flagged too (Excel shows `#NAME?`; Mind: "No function found … not a
  function"), with the closest existing name proposed — table names, names of any
  alphabet, names with `?`, sheet-qualified references and LET variables are not flagged.
- **RSK-002 — array formulas exceeding the grid**: a header cell merged over several
  columns now counts for every column it spans, as Mind reads it. An array formula running
  past the header columns is reported in Mind's own words, with the first cell outside the
  grid. (Mind had refused a model for `Temp!F5` that the tool had let through.)
- **FRM-005 — circular references** (new): Mind's runner stops on "Circular reference
  found". The tool builds the dependency graph of every formula (cells, ranges, defined
  names) and reports each cycle as its chain of cells, plus whether Excel's iterative
  calculation is on. Cycles that only close through an IF/IFERROR/CHOOSE branch are a
  warning (Excel computes them; Mind's answer is not documented). A cell that reads its
  own address on a sheet chosen at run time (`INDIRECT` + `ADDRESS(ROW(),COLUMN())`) is
  the pattern Mind stopped on, and is reported as such. Verified on the RAROK model
  (70,861 such cells) and on PVFP / Horizon / CNHI (no false cycle). No automatic repair: the Mind mechanism for a value feeding the next
  round is `MM_ITERATIONS` with `/iterationinput` and `/iterationoutput`.
- **FRM-006 — 3-D references** (new): `'First:Last'!cell` spans every sheet between two
  tabs; Mind reads `First:Last` as one sheet name and fails ("Sheet … not found in
  workbook on compiling formula"). The sheets spanned are listed in tab order and the
  explicit per-sheet formula is proposed, to apply by hand or with the assistant. Verified
  on the PVFP model: 10,404 references rewritten through the app, rule passes afterwards,
  the Excel recalculation shows the same error cells before and after (65,883, all from the
  model's external links).
- **FRM-002 — functions** now says only what the Mind documentation says. The KB page
  "Supported Excel formulas" (last updated 2021-11-17) names the functions Mind supports and
  says nothing about the others; a native function missing from it is a **warning
  ("not documented")**, not a blocker. Functions Mind accepts beyond the page are recorded
  with their evidence in `references/mind-confirmed-functions.yaml` (FILTER — proven by a
  conversion; IFNA, INDIRECT, XLOOKUP — stated by the tool's owner). An MM_ function missing
  from the MM_ registry stays an error.
- **STR-001 — trapped titles**: a `#Title` sitting on its grid's first row is left for
  manual repair with the reason, instead of being re-planned every round (the cause of the
  endless Prep rounds seen on a real model).
- **Recalculation**: error cells that were already errors in the original upload are
  classified as pre-existing; only *new* errors count against a fix and keep the verdict
  from turning green.
- Formulas are shown as Excel shows them (`=NUMBERVALUE(A1)`), without the `_xlfn.` storage
  prefix, so a copied formula never carries it.

## 4. Assistant

- Every claim about Mind must come from the Mind documentation the tool holds; general
  Excel knowledge is not evidence. A "Function support" block gives the tool's verdict for
  each function a question names, with the workbook's usage and the evidence. A function
  the documentation does not list is described as *neither confirmed nor refused*; the
  assistant proposes a replacement only when asked.
- Calls the gateway's native Messages passthrough (`/anthropic/v1/messages`); the former
  route answered HTTP 200 with an empty body.
- Proposals get 4000 tokens and must keep the original behaviour on blank cells; the Fix
  panel says up front when a proposal covers fewer cells than the finding counts.

## 5. Findings, History, navigation

- The Fix column routes to Prep when Prep holds the change ("Repair in Prep (N)"), shows a
  BY HAND tag when Prep left every site for review, and "Fix with assistant" otherwise.
- "By hand" next to every Prep repair: the Fix panel opens on the same cells.
- Any version can be restored as current from History.

## 6. Launching the app

- VS Code: a Run/Debug configuration ("Mind Ready server", F5) and a build task.
- `run_mind_ready_web.bat`: uses the project's `.venv`, starts the server in its own window,
  opens the browser once `/api/health` answers (checked on 127.0.0.1).
- Starting the server while it is already running now says so and opens the app, instead of
  failing on "port 8600 already in use".
