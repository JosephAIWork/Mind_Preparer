# Raw insights from editor D (app comments before the release cleanup)

- UC-5 | excel_worker.py | Excel per step | Opening the 179 MB Phoenix version in Excel took a minute per step of Do everything; one held Excel per session (excel_worker) removed those opens.
- UC-3 | formula_utils.py | scan memo | CNHI: 1.7 million cell_refs_in_formula calls for 245,847 formulas in one scan, one rule after another -> formula_memo works each answer out once per formula text. The mask cache (65,536) is far smaller than CNHI's formula count.
- UC-2 | formula_utils.py | mask_strings | Palermo: 4.4 million mask_strings calls for 57,537 formulas; most hold no quote, so the early return skips them.
- UC-1 | formula_utils.py | find_calls_detailed | Horizon: about a million find-call questions per scan; a formula that does not contain the function name cannot call it (ASCII shortcut).
- UC-1 | formula_utils.py | reference-only arguments | 2026-09-24: an assistant fix rewrote SUMIFS('BASE Polices'!#REF!, ...) to SUMIFS(NA(), ...) in 17 cells and Excel refused every one (COM 0x800A03EC) -> REFERENCE_ARGS list.
- UC-3 | inventory.py | bounded workbook cache | CNHI (36 MB): unbounded per-version workbook caches took the web server past 13 GB and the machine out of memory -> _BoundedCache.
- UC-2 | inventory.py | blank cells | Palermo: ws.iter_rows() creates 5.4 million blank cells for the used rectangle -> iterate ws._cells.
- UC-2 | inventory.py | style proxies | Palermo: reading cell.font/fill/number_format built 13 million style proxies (two minutes) -> styles worked out once per (font, fill, numFmt).
- UC-5 | inventory.py | pivot grouped fields | Phoenix: a grouped pivot field is what Mind's converter could not read.
- UC-3 | inventory.py | MM_ formulas | CNHI: the rules ask for one MM_ function after another (38 passes per scan) over 245,847 formulas -> _mm_formulas filters once.
- UC-2 | fast_xlsx.py | XML parser | Palermo (27 MB, 5.7 million used cells): half of the load time was defusedxml's Python handlers; the data_only second load cost another six minutes.
- UC-1 | fast_xlsx.py | parser benchmark | Horizon: stdlib expat iterparse 5.4 s vs defusedxml 7.4 s vs lxml 10.6 s.
- UC-4 | external_links.py | external links | PVFP: the link points to a file on a colleague's machine; 20,934 formulas live on the external-link cache (example formula ='[1]General Assumptions'!$D$13*H21).
- UC-5 | pivots.py | pivot tables | Phoenix TVOG: Mind's converter stopped with "The method or operation is not implemented"; with its pivot tables turned into values the same file was accepted.
- UC-2 | recalc.py | error cells | Palermo: reading the whole used range (values + formulas) to find error cells took 47 s on 5.7 million cells at every recalculation -> SUMPRODUCT count + SpecialCells.
- UC-5 | autofix.py | multi-area writes | Phoenix: clearing 10,002 error constants one Excel call each took most of the fixer's 977 s of writing -> multi-area ranges.
- UC-4 | model_map.py | key cell without macro | PVFP has no macro loop; its key is 'LoB 1'!G2; dropdown over a block of named flags LoB1_Boolean ... in G51:G60.
- UC-1/UC-2/UC-3 | model_map.py | labelled settings | 'label | value' pairs live on Horizon's Parametres (label on one row, number on the next), Palermo's Macro and Control sheets, CNHI's Model Inputs.
- UC-1 | model_map.py | per-item driver | Horizon: driver CALCUL!A2:NI2 <- BASE Polices row n.
- UC-3 | loop_builder.py | dropdown drops MM_LOOP | 2026-10-16: Mind dropped the MM_LOOP written into CNHI's two driver cells because they carry a list dropdown (also seen in a probe workbook) -> remove_validation op.
- UC-2 | loop_builder.py | counter driver | Palermo: Projection!C3 = polProcess is the loop counter itself.
- UC-3 | loop_builder.py | derived driver | CNHI: active_year = proj_year + i - 1.
- UC-2 | loop_builder.py | stale paste area | Palermo: Macro!A13 = ... + OFFSET(V13, ...) over the per-tariff results the macro pastes (Macro!V13:JU140, 728 stale values from an old run); the macro clears them first, so the loop plan clears them too.
